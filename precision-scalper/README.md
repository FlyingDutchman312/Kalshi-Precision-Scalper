# Precision Scalper V1.0
Standalone research-only market scanner. No order endpoints or Kalshi credentials. Node 22+, no dependencies. `npm test`, `npm start`, then http://localhost:3000.

Deploy: create a new private GitHub repo, upload these files at the root (keep public/index.html in public). Create a new Supabase project or run schema.sql in an existing project's SQL editor; this creates only a new isolated table. In Render create a Web Service from the repo, build command `npm install`, start `npm start`. Set SUPABASE_URL to project URL and SUPABASE_SERVICE_ROLE_KEY to server-side legacy service_role key. Never commit keys. Optional environment settings MIN_PRICE_CENTS=90, MAX_PRICE_CENTS=96, WINDOW_SECONDS=180, MAX_SPREAD_CENTS=2. Use always-on hosting for continuous collection; free services may sleep. Dashboard is public and contains market data and observation history only; do not add private account information. Without storage the live scanner works but no observations are saved.

One first qualifying quote per ticker is saved via database primary key. Settlement catch-up checks pending records after close and records only finalized binary results. No assumed fills, fees, profits, or model probabilities. Polling is best effort, not tick-level; quote retrieval time is not exchange quote timestamp. Series names use conventional KX{symbol}15M and must be verified in deployment. Dashboard journal is limited to 100 recent rows. Live external API and Supabase integration must be verified after deployment. For more robust production research, add a dedicated worker, quote timestamps, pagination and settlement retry monitoring.

## V1.1 upgrade
Run schema_v11.sql in the existing Supabase SQL editor first. Replace files in the existing precision-scalper directory, preserving Render root and environment variables. No order routes or credentials. Coinbase Exchange USD spot proxies (BNB via Binance.US BNBUSD) may be unavailable or stale; no model estimate is emitted in that case. The zero-drift normal model uses a projected 60-second average with an assumed 5bp basis floor, not official CF index observations or calibrated probabilities. Checkpoints are first valid snapshot within 12 seconds after 180/120/60/30 seconds remaining, duplicate-protected. Missing snapshots are not backfilled. Compare paired Brier scores; latest 100 rows are not independent samples. No fee or execution simulation in this release.

## V1.2
No schema migration. Historical quote scenarios are derived from the existing durable baseline journal, using whole contracts and a $5 all-in hypothetical budget, standard multiplier 1 and conservative cent-rounded fee estimates. No fills, capital allocation, trading signals or orders. History capped at 10,000 records; latest 100 scenarios displayed. Model Brier comparison remains separate; model-filtered profitability is not implemented because V1.1 did not persist executable ask quotes alongside model checkpoints. Kraken BNB/USD is attempted if Binance.US fails; availability must be verified on Render. Switching sources resets model warmup rather than mixing prices.

## V1.2.1 reliability patch
Accepts query strings on dashboard/API routes, adds automatic reconnect status and local-file warning, and tries Coinbase Exchange BNB-USD before existing fallbacks. Actual trade timestamps and the 12-second freshness limit remain mandatory. Live provider availability must be checked after deployment. No SQL changes; all orders disabled.

## V1.3 forward strategy research
Run `schema_v13.sql` in Supabase before deployment. Existing tables and environment variables are unchanged. Four fixed experimental policies collect separate first qualifying observations per strategy/ticker, starting at deployment (no backfill). Reports use hypothetical $5 all-in whole-contract scenarios and official settlement, not fills. Current rejection reasons are displayed; rejection history is not persisted. Each strategy report is capped at the latest 10,000 records. Quote freshness uses local fetch time, not an exchange event timestamp. BNB remains baseline-only whenever its timestamped spot providers fail; no new provider is guaranteed. No order execution exists.
